# 智能药房后台：老项目布局现代化设计规格

## 1. 目标

新后台保留老项目已经验证过的业务信息架构和页面布局，将老旧 EasyUI 视觉替换为现代、克制、高密度的企业级 UI。

本规格解决两个问题：

1. 业务页面不能因为“美化”而丢失筛选项、表格列、操作入口、状态和分页。
2. 视觉不能继续使用老项目的过时样式，也不能变成低密度、卡片堆叠的通用 AI 后台。

本规格取代 2026-08-11 三阶段 Stitch 规格中的视觉方向、应用壳层和页面布局规则；旧规格仍可用于核对阶段范围和已确认业务名词。出现冲突时以本规格和老项目截图基线为准。

## 2. 设计依据与优先级

设计冲突按以下优先级处理：

1. `docs/00_项目总览/老项目UI截图基线`：决定父子菜单、页面结构、字段密度、业务控件和操作顺序。
2. 当前新项目 API、权限和新增业务：决定 69 个新路由的真实功能，不为复刻老页面删除新能力。
3. IBM Carbon 的企业级产品原则：决定网格、层级、表格密度、平面化和语义色。
4. TDesign Vue Next：决定可实际交付的组件、交互和可访问性实现。
5. Impeccable：只用于最终反模式审查和精修，不负责改变业务布局。

`getdesign.md` 的 IBM `DESIGN.md` 是独立分析和灵感起点，不是 IBM 官方授权模板。本项目不使用 IBM 标识，不复制 IBM 营销页，不使用 42px–76px 营销标题，也不照搬其品牌文案。

## 3. 信息架构

- 老系统实际菜单为 11 个父级、64 个子页面。
- 新系统保留 69 个业务路由；新增或拆分的 5 个入口复用最接近的老页面布局模板，但展示新系统真实字段和操作。
- 父级顺序以截图基线为准：系统、参数、机构、物流、订单、维护、标签、短信、药品、报表、煎煮。
- 默认只展开当前父级菜单；切换父级时关闭上一组。
- 菜单名称以最终业务词典为准，旧名称只作为截图映射，不直接回退新系统已确认的命名。

## 4. 视觉方向

方向名称：**现代企业医疗运营台**。

关键词：高密度、平面、清晰、可信、低装饰、强扫描性。

禁止：

- 大面积圆角卡片、卡片嵌套、悬浮区块和柔光阴影。
- 紫色渐变、玻璃拟态、发光、装饰性圆球和营销插画。
- 大标题、大留白、虚构指标、无业务价值的说明文案。
- 把所有按钮做成胶囊，把所有状态做成高饱和标签。
- 为追求简洁删除老页面的业务字段或操作。

## 5. 设计令牌

### 5.1 颜色

| 用途 | 色值 | 规则 |
| --- | --- | --- |
| 品牌主色 | `#0052D9` | 主按钮、链接、当前菜单、焦点，不铺满大面积容器 |
| 主色悬停 | `#003CAB` | 主按钮和链接悬停 |
| 顶栏/侧栏 | `#1F2D3D` | 延续老项目深色工作台结构 |
| 侧栏悬停 | `#26384A` | 普通菜单悬停 |
| 侧栏选中 | `#0B5CAB` | 当前子菜单背景或左侧指示条 |
| 页面背景 | `#F5F6F7` | 页签以下工作区 |
| 主表面 | `#FFFFFF` | 页面、表格、抽屉和弹窗 |
| 次表面 | `#F2F3F5` | 表头、筛选带、禁用区域、隔行背景 |
| 主文字 | `#181818` | 标题、表格主值 |
| 次文字 | `#5E5E5E` | 标签、辅助值、时间 |
| 弱文字 | `#8B8B8B` | 占位、禁用和次要说明 |
| 分割线 | `#DCDCDC` | 表格、控件和区域边界 |
| 成功 | `#2BA471` | 启用、成功、已完成 |
| 警告 | `#E37318` | 待处理、超时风险 |
| 危险 | `#D54941` | 失败、停用和危险操作 |

颜色面积应由白色、浅灰和深色导航占 90% 以上；蓝色只表达选择、焦点和主操作。

### 5.2 字体与尺寸

- 不依赖境外字体 CDN；使用系统无衬线字体栈：`-apple-system, BlinkMacSystemFont, "Segoe UI", "Microsoft YaHei", sans-serif`。
- 页面标题：20px / 600，行高 28px。
- 区域标题：15px / 600，行高 22px。
- 表单、按钮、表格：13px–14px。
- 辅助信息和分页：12px。
- 数字使用等宽数字特性，字距统一为 0。

### 5.3 几何与间距

- 采用 4px 基础网格；常用间距为 4、8、12、16、24px。
- 输入框、按钮、下拉框默认高度 32px；触屏断点提高到至少 40px。
- 控件圆角 2px–4px；面板、抽屉、弹窗最大 4px；状态标签可使用小圆角，不使用胶囊按钮。
- 表格表头 40px，数据行 40px；多行内容按需增高，不固定裁切。
- 默认无阴影；抽屉和弹窗可使用一层克制阴影表达遮挡关系。

## 6. 应用壳层

保留老项目“顶栏 + 左侧菜单 + 页签 + 主工作区”的布局。

- 顶栏高度 48px，深色；左侧为“智能药房 SaaS”，右侧为租户、用户和退出。
- 侧栏宽度 208px，深色；支持收起到 56px。
- 父级菜单高度 40px，子级菜单高度 36px；展开项不改变其他菜单宽度。
- 当前父级使用蓝色文字/图标，当前子级使用 3px 左侧蓝色指示条和深色选中背景。
- 页签栏高度 36px，白色，底部细分割线；只保留关闭和更多操作，不做胶囊页签。
- 内容区默认 12px–16px 内边距；页面主表面与工作区平齐，不把整个页面放进浮动卡片。
- 1024px 以下侧栏改为抽屉；复杂生产作业页以桌面端为主，移动端保证查询、查看和基础操作。

## 7. 标准页面模板

### 7.1 列表查询页

```text
页面标题                                      页面级操作
筛选带：标签+控件 ...                   查询 重置 更多筛选
批量操作/结果摘要（仅在真实需要时出现）
数据表格
总数/选中数                                      分页
```

- 标题、筛选、表格和分页是一个连续工作面，不拆成多个悬浮卡片。
- 筛选条件按老截图顺序排列；常用条件首行展示，超出部分折叠到“更多筛选”。
- 查询为主按钮，重置为次按钮；导出和新增位于页面右上或表格工具栏。
- 表格表头浅灰，行悬停使用极浅蓝灰；数值右对齐，短状态居中，文本左对齐。
- 首列优先展示业务名称/编号，不直接展示 UUID。
- 行内显示 1–2 个高频操作，其余放入更多菜单；危险操作不能与查看使用相同颜色。
- 宽表格只在表格容器内部横向滚动，固定关键列和操作列。

### 7.2 新增与编辑

- 普通主数据使用右侧抽屉，宽 480px–640px。
- 字段较多或有步骤依赖的业务使用独立页，不塞进超长弹窗。
- 标签位于控件上方或稳定左列；同一页面只使用一种标签布局。
- 底部操作固定为“取消 / 保存”，危险变更显示影响对象并二次确认。
- 密钥、Token、完整手机号等敏感字段默认不回显。

### 7.3 详情页

- 以无卡片分区、描述列表、明细表和时间线组织内容。
- 分区使用标题、细分割线或浅灰带，不使用卡片套卡片。
- 订单、处方、患者、配送、费用和操作日志保持清楚边界。
- 姓名、手机号、地址和异常请求内容按权限脱敏。

### 7.4 作业页

- 审核、调剂、复核、打印、煎煮和发货保持老系统的任务优先布局。
- 扫码/输入区放在首屏明显位置，当前任务和主操作必须无需滚动即可触达。
- 主操作只能有一个视觉主按钮；后退、取消、异常处理使用次级或危险样式。
- 设备、打印机、桶号和当前流程状态必须持续可见，不用装饰性指标替代。

### 7.5 报表页

- 保留老系统的时间、机构、人员等筛选结构和明细表。
- 没有真实指标时不增加图表；真实适合趋势或构成的数据才使用图表。
- 汇总值使用紧凑摘要条或表格首行，不使用大面积营销指标卡。

## 8. TDesign 组件约束

- 优先使用 `t-input`、`t-select`、`t-date-range-picker`、`t-button`、`t-table`、`t-pagination`、`t-drawer`、`t-dialog`、`t-tabs` 和 `t-tag`。
- 图标统一使用 TDesign Icons；图标按钮必须有 tooltip 或可访问名称。
- 通过全局主题变量和少量公共后台组件统一样式，不在 69 个页面重复覆盖 CSS。
- 公共组件只负责布局、密度和状态，不改变页面 API 调用与业务权限。
- 禁止在原生控件和 TDesign 控件之间随机混用，除非打印或设备页面有明确兼容约束。

## 9. 外部工具使用方式

### 9.1 getdesign.md

- IBM `DESIGN.md` 只作为颜色、网格、平面层级和密度的参考输入。
- 本规格中的项目令牌优先于下载文件；不得让外部文件覆盖业务页面模板。
- 不复制 IBM 品牌名、Logo、营销结构和大字号展示体系。

### 9.2 Impeccable

- 页面完成后运行 `audit`、`distill`、`polish` 类检查。
- 审查重点：卡片嵌套、过度圆角、装饰性状态标签、层级不清、焦点状态、溢出和对齐。
- Impeccable 的建议若删除业务字段、改变工作流或降低信息密度，应拒绝并以截图基线为准。

## 10. 实施分期

1. **基础壳层与公共模板**：应用壳、菜单、页签、筛选带、表格、分页、抽屉和状态组件。
2. **基础管理页**：系统、参数、机构，共 11 个老页面基线及对应新路由。
3. **核心履约页**：物流、订单、煎煮，共 23 个老页面基线及对应新路由。
4. **运营支撑页**：维护、标签、短信、药品、报表，共 30 个老页面基线及对应新路由。

每一期先选 1 个代表页面完成截图对比并确认，再扩展到同类页面。不得一次性只改全局 CSS 后宣称 69 页完成。

## 11. 验收标准

- 11 个父级菜单与截图基线顺序一致，单组展开正确。
- 69 个新路由均可访问，新增业务未因复刻老页面丢失。
- 每个页面可追溯到一张老项目截图或明确的相邻模板。
- 主要筛选字段、表格列、状态、操作和分页与老业务结构一致。
- 页面无卡片套卡片、无大面积无意义留白、无营销式标题和虚构数据。
- 1440×900、1366×768、1024×768 和 390×844 无不合理重叠；宽表格只在内部滚动。
- 加载、空数据、错误、无权限、只读、禁用和提交中状态完整。
- 姓名、手机号、地址、密钥、Token 和原始异常内容按权限处理。
- 生产构建通过；代表页面完成桌面与移动端截图对比；最终通过 Impeccable 反模式审查。

## 12. 回滚边界

- 视觉重构不修改后端 API、数据库、权限模型和业务状态机。
- 每个分期独立提交、独立部署；线上继续保留上一个健康前端镜像。
- 如代表页面验收失败，回滚该分期组件和页面，不影响上一期已确认范围。
