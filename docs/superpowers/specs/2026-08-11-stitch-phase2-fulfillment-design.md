# Stitch 第二阶段：核心履约作业

## 1. 阶段范围

第二阶段包含 3 个父级菜单、26 个业务入口：

| 父级菜单 | 页面数 | 页面 |
| --- | ---: | --- |
| 订单管理 | 14 | 处方列表、订单审核、调剂打印、单桶复核、多桶复核、复核管理、地址修改、处方修改、订单操作、处方重打、订单仓库、订单拦截、订单走流程、订单签收 |
| 煎煮管理 | 5 | 设备列表、处方设备绑定、打码机配置、加水桶管理、云打印记录 |
| 物流管理 | 7 | 机构物流费规则、地址物流费、订单发货、物流轨迹、物流打单、物流合并、未签收跟进 |

## 2. 生成顺序

1. 处方列表与订单详情工作台。
2. 审核、调剂、单桶/多桶复核作业。
3. 煎煮设备与绑定作业。
4. 物流发货与打印。
5. 修改、补偿、拦截、签收和跟进页面。

## 3. 核心信息模型

订单详情不能压成一张超宽表。使用以下分段：

```text
订单摘要：订单号、机构、状态、时间、配送方式
患者与收货：脱敏患者信息、地址、联系方式
处方分组：处方属性、医生、科室、诊断、剂数
药品明细：药品、规格、产地、剂量、数量、金额
费用：药品、煎煮、配送、结算金额
流程时间线：接单、审核、调剂、复核、煎煮、发货、签收
操作记录：操作人、原因、结果、时间
固定操作栏：当前阶段允许的动作
```

## 4. 代表性页面

### 4.1 处方列表

- 常用筛选：时间、机构、订单/处方号、患者、状态。
- 更多筛选：处方类型、门诊/住院、配送方式、煎煮中心。
- 表格优先展示处方号、机构、患者脱敏名、剂数、当前阶段、配送方式和关键时间。
- 点击主值进入详情，不把所有字段放入列表。

### 4.2 订单审核

- 左侧任务列表，右侧或主区域展示处方分段详情。
- 固定操作栏：通过、驳回、修改地址；驳回必须填写原因。
- 显示任务锁定和版本冲突，不允许重复提交。

### 4.3 调剂与复核

- 强调当前处方、药品明细、剂数、桶号、操作员工号和打印状态。
- 扫码输入区稳定，不因提示信息跳动。
- 单桶与多桶复核分别生成，不把两种流程强行合并。

### 4.4 煎煮设备绑定

- 设备状态、占用关系、处方与桶号是主信息。
- 绑定、解绑和重绑显示冲突结果与影响对象。
- 设备列表使用状态点和最近心跳时间，不使用装饰性设备卡片。

### 4.5 物流发货与打单

- 发货查询和物流打单是两个独立页面。
- 打印页左侧任务/订单，右侧固定纸张预览与打印设置。
- 重打必须选择原因，显示历史打印结果。

## 5. 高风险动作

以下动作必须有确认、原因、提交中和结果反馈：

- 审核驳回、调剂完成、复核完成。
- 地址/处方修改、取消、初始化和手工走流程。
- 处方重打、物流打单/重打、物流合并。
- 设备解绑/重绑、手工签收、批量签收。
- 拦截规则修改和费用规则导入。

## 6. Stitch 阶段 Prompt

```text
这是第二阶段“核心履约作业”，请生成订单管理、煎煮管理和物流管理的高保真作业后台，共 26 个业务入口。

先生成 8 个代表性屏幕：处方列表、订单详情工作台、订单审核、调剂打印、单桶复核、多桶复核、煎煮设备绑定、物流打单。确认操作密度和状态体系后，再扩展其余订单修改/补偿/仓库/拦截/签收、煎煮设备配置、物流费用/发货/轨迹/合并/未签收跟进页面。

该阶段是生产作业界面，不使用营销式卡片或装饰图表。订单详情按订单、患者、处方、药品、金额、配送、流程和操作记录分段；审核、调剂、复核和打印有固定操作栏。所有推进状态的按钮必须有禁用、提交中、冲突、失败和成功反馈。使用脱敏患者数据，禁止显示完整手机号和身份证。
```

## 7. 第二阶段验收

- 26 个入口独立存在，查询页与作业页不混淆。
- 订单详情字段分段清楚，首屏能判断当前阶段和下一步动作。
- 单桶、多桶、打印和设备绑定具有不同的专用布局。
- 高风险动作有原因、确认、锁定和结果反馈。
- A5 单据、标签和面单预览保持固定尺寸。
