# Stitch 第三阶段：运营支撑与分析

## 1. 阶段范围

第三阶段包含 4 个父级菜单、25 个业务入口：

| 父级菜单 | 页面数 | 页面 |
| --- | ---: | --- |
| 标签管理 | 2 | 处方标签设置、处方标签打印 |
| 短信管理 | 3 | 短信模板、单发短信、短信记录 |
| 维护管理 | 4 | 订单流程、异常日志、MQ 消息、问题件登记 |
| 报表管理 | 16 | 处方量、机构处方量、5 类人员绩效统计与明细、机构药材对账、处方对账、药材明细、药材用量 |

## 2. 生成顺序

1. 标签模板与打印工作台。
2. 异常日志与 MQ 消息排障工作台。
3. 问题件处理和短信发送。
4. 一组绩效汇总与明细钻取模板。
5. 其余 16 个报表按统一模板扩展。

## 3. 代表性页面

### 3.1 标签模板与打印

- 模板列表显示适用范围、机构、处方类型、尺寸、状态和更新时间。
- 编辑使用 Drawer，固定尺寸预览单独占据稳定区域。
- 打印工作台包含任务、打印机、份数、预览、结果和重打原因。
- 不用浏览器自适应缩放破坏毫米尺寸。

### 3.2 异常日志

- 筛选：时间、订单号、机构、阶段、错误类型、处理状态。
- 表格主信息：业务阶段、错误摘要、关联订单、发生时间、恢复状态。
- 原始堆栈、请求体和技术字段放详情 Drawer 的诊断区，不进入主列表。

### 3.3 MQ 消息

- 区分生产、发送、消费、失败、重试、死信和回调状态。
- 主列表显示业务事件名称、关联订单、当前阶段、失败原因和最近时间。
- 重放/重试必须显示影响范围、次数限制和审计提示。

### 3.4 问题件登记

- 主列表显示订单、机构、问题类型、处理状态、责任环节、金额和更新时间。
- 详情使用时间线展示登记、方案、处理、关闭过程。
- 关闭必须填写结果和原因。

### 3.5 报表汇总与明细

- 汇总页：时间、机构/中心/人员筛选，关键总数，趋势或排名，汇总表和明细入口。
- 明细页：保留筛选条件上下文，显示记录表和导出。
- 审核员、调剂员、复核员、煎煮员、物流员五类绩效使用同一结构，不复制五套视觉。
- 对账类页面强调金额、数量、差异和核对状态；数字右对齐。
- 大范围导出显示异步任务状态，不伪装成立即下载。

## 4. 状态与风险

- 短信发送和重试需要二次确认、提交中和失败原因。
- MQ 重放、异常手工处理和问题件关闭是高风险动作。
- 报表必须显示统计口径、时间范围和数据更新时间。
- 打印失败、短信失败、消息死信和导出失败必须有恢复入口。

## 5. Stitch 阶段 Prompt

```text
这是第三阶段“运营支撑与分析”，请生成标签、短信、维护和报表管理的高保真页面，共 25 个业务入口。

先生成 7 个代表性屏幕：标签模板列表、标签打印工作台、异常日志列表与诊断 Drawer、MQ 消息列表与重放确认、问题件详情时间线、审核员绩效汇总、审核员绩效明细。确认模板后，再扩展短信页面和其余报表。

维护页面是排障工作台，主列表优先显示业务阶段、原因和恢复动作，原始日志与技术字段放诊断详情。报表保留汇总到明细的钻取关系，蓝/青/绿用于正常数据，橙/红只表示风险和异常。标签与打印必须保持固定纸张尺寸，不使用普通响应式卡片替代预览。
```

## 6. 第三阶段验收

- 25 个入口在菜单中独立可达。
- 打印、短信、异常、MQ 和问题件都有完整失败与恢复状态。
- 16 个报表共享统一框架，但保留各自统计字段与明细入口。
- 技术字段不占据主列表，业务原因和处理状态优先。
- 图表不过度彩色，不生成无业务依据的指标。
