# Stitch 第一阶段：基础资料与权限

## 1. 阶段范围

第一阶段包含 4 个父级菜单、18 个业务入口：

| 父级菜单 | 页面数 | 页面 |
| --- | ---: | --- |
| 系统管理 | 3 | 用户管理、角色管理、菜单管理 |
| 参数管理 | 4 | 字典列表、参数配置、煎煮中心配置、工号管理 |
| 机构管理 | 5 | 机构列表、机构应用配置、机构 IP 白名单、接口列表、机构接口权限 |
| 药品管理 | 6 | 药品目录、药品索引日志、药品索引、药品目录导入、药品索引导入、药材区域 |

其中“机构应用配置”是新系统新增能力，其余 17 个入口来自老项目菜单。

## 2. 生成顺序

不要一次生成 18 张互不相关的图。按以下顺序在同一个 Stitch 项目中扩展：

1. 应用壳层与机构列表。
2. 角色管理与授权 Drawer。
3. 药品目录与药品索引。
4. 药品导入分步流程。
5. 其余同类配置页面沿已确认组件扩展。

## 3. 关键页面设计

### 3.1 机构列表

- 筛选：机构编码/名称/煎煮中心、状态、类型。
- 表格：机构名称与编码、类型、状态、煎煮中心、创建时间、更新时间、操作。
- 动作：查询、重置、导出、新增、编辑、启停。
- 新增/编辑放右侧 Drawer；启停二次确认。

### 3.2 机构应用配置

- 筛选：关键字、机构、状态。
- 表格：机构、AppKey、签名类型、密钥配置状态、回调地址、状态、更新时间。
- 密钥只显示“已配置 / 未配置”；编辑时不回填密钥。
- 填写新密钥时明确提示“保存并重置密钥”。

### 3.3 角色管理

- 左侧或主表显示角色名称、编码、成员数、状态和更新时间。
- 点击编辑后使用宽 Drawer，包含基本信息、权限域分组、机构范围和危险操作。
- 权限按系统、订单、机构、药品、物流、煎煮、报表等业务域分组，不使用超长窄栏。

### 3.4 药品目录

- 筛选：药品编码、名称、规格、产地、状态。
- 表格：药品名称与编码、规格、产地、单位、零售价、状态、更新时间。
- 动作：新增、编辑、启停、导出、进入导入。
- 金额右对齐，编码和数量使用等宽数字。

### 3.5 药品索引

- 明确区分“机构药品”和“平台药品”。
- 表格主列使用上下两行显示名称与编码，避免全是技术编码。
- 动作包含新增映射、编辑、启停和查看操作日志。

### 3.6 药品导入

- 使用四步流程：模板与规则、选择文件、预检结果、导入结果。
- 预检显示总行数、可导入、重复、错误；错误行可下载。
- “覆盖已存在”使用开关，并在执行前说明影响。

## 4. 同类页面扩展规则

- 字典、系统参数、煎煮中心、工号、IP 白名单、接口定义、接口授权和药材区域复用“列表 + Drawer”结构。
- 菜单管理使用树形表格；父子关系必须可扫描。
- 接口路径、回调地址和备注允许换行，不扩大表格到页面外。
- 白名单、接口授权、系统参数和角色授权属于安全配置，保存前需要二次确认与影响说明。

## 5. Stitch 阶段 Prompt

将全局 C1 Prompt 与以下内容一起粘贴：

```text
这是第一阶段“基础资料与权限”，请在同一设计系统中生成系统管理、参数管理、机构管理和药品管理的高保真页面，共 18 个业务入口。

先生成 6 个代表性屏幕：应用壳层、机构列表、机构应用配置、角色管理及授权 Drawer、药品目录、药品导入预检结果。确认组件规范后，再扩展用户、菜单、字典、系统参数、煎煮中心、工号、IP 白名单、接口定义、接口授权、药品索引、索引日志、索引导入和药材区域。

列表是主工作区，新增和编辑使用 Drawer/Dialog。不要把每个页面都设计成指标卡仪表盘。机构应用不得显示密钥明文；角色授权按业务域分组；药品导入必须包含模板、文件、预检和结果。所有数据使用脱敏中文示例，保持桌面高信息密度。
```

## 6. 第一阶段验收

- 18 个入口在左侧菜单中均可定位。
- 至少形成列表页、树形权限页、导入页三种稳定模板。
- 机构与药品名称优先，编码作为次级信息。
- 安全配置和高风险动作有确认与错误反馈。
- 页面不含密钥、密码、Token、UUID 主列或虚构指标。
