# 智能药房 SaaS 后台 React 并行重建设计

日期：2026-08-15

## 决策

本规格替代同日早先的 Vue/TDesign 局部 UI 基线方案。用户已明确要求放弃继续修 Vue 前端，改为新建 React 前端；老项目只作为功能、菜单、页面结构和操作流程的事实来源，不复制旧样式和旧技术实现。

最终方向：

- 新建 `frontend/admin-react`，并行开发 React 管理后台。
- 暂时保留 `frontend/admin-web` Vue 工程，React 版验证通过后再切换部署入口。
- 老项目截图基线和老项目审查报告作为页面结构事实源。
- 新视觉采用现代高密度企业后台风格，保留老系统工作习惯。

### 老项目审查报告

`docs/00_项目总览/老项目审查报告.md` 已恢复出老后台 11 个一级菜单、68 个二级菜单。新前端必须以这张菜单清单作为功能地图，而不是只保留少量概览页。

老项目主框架是 EasyUI Layout：

- 顶部 48px 系统栏。
- 左侧 200px Accordion 父子菜单。
- 中央 EasyUI Tabs。
- 每个业务页面通过 iframe 打开。

该结构的业务价值是：同时保留多个工作页面、快速切换、按父级菜单组织高频后台操作。React 版要保留这个操作习惯，但必须去掉 JSP、iframe、jQuery、EasyUI、Bootstrap 内联样式和固定像素技术债。

### 当前新项目现状

当前仓库只有一个前端工程：

`frontend/admin-web`

现状：

- Vue 3 + Vite + TypeScript + TDesign Vue Next。
- 已有 API client、登录鉴权、刷新 token、网关代理和部分页面。
- API 前缀覆盖 `auth-api`、`order-api`、`workflow-api`、`logistics-api`、`message-api`、`report-api`、`decoction-api`、`integration-api`、`callback-api`、`ops-api` 等。

React 重建应优先复用接口契约和类型信息，但不复用 Vue 组件、Vue Router、TDesign Vue 样式和 `base.css`。

## 目标

第一阶段目标不是一次性完成 68 个菜单的所有业务细节，而是建立 React 新前端的可持续架构和代表页面样板：

- 搭建 `frontend/admin-react` 工程。
- 恢复老后台 11 个父级菜单和 68 个业务入口的路由地图。
- 接入现有后端登录、会话、权限、菜单和 API 代理。
- 实现现代后台主壳层：顶部栏、左侧父子菜单、可关闭页签、中央工作区。
- 按老截图结构实现代表页面样板，覆盖列表、配置、订单工作台、报表、打印/作业入口。
- 建立统一的查询表格、编辑抽屉、确认弹窗、状态标签、导入导出、空状态、错误状态和加载状态。

## 非目标

- 不直接删除 `frontend/admin-web`。
- 不修改后端接口、数据库、权限语义、业务状态机。
- 不复制老项目 JSP、iframe、jQuery、EasyUI、Bootstrap 代码。
- 不复制 Stitch 生成图中的混乱菜单和不一致布局。
- 不在第一阶段承诺 68 个菜单全部达到生产级完整功能。
- 不提交 `.superpowers/`、浏览器临时文件、截图草稿、密钥、账号密码或构建产物。

## 技术栈

React 新工程采用：

- React
- TypeScript
- Vite
- Ant Design
- ProComponents
- React Router
- TanStack Query

选择理由：

- Vite 继续作为轻量现代构建工具，适合独立前端工程。
- Ant Design 面向企业级 React 管理后台，组件覆盖表格、表单、弹窗、导航、反馈和国际化。
- ProComponents 能减少中后台 CRUD、筛选表格和表单页的重复样板代码。
- React Router 管理路由、嵌套路由和页面入口。
- TanStack Query 管理服务端状态、缓存、刷新、错误和重试。

## 架构设计

### 目录边界

React 工程位于：

`frontend/admin-react`

建议结构：

```text
frontend/admin-react
├─ src
│  ├─ app              # 应用启动、Provider、路由注册
│  ├─ shell            # 主壳层、菜单、页签、顶部栏
│  ├─ routes           # 11 个父级菜单与 68 个入口路由配置
│  ├─ api              # request、token、业务 API 封装
│  ├─ features         # 按业务域组织页面
│  ├─ components       # 查询表格、编辑抽屉、状态标签等通用组件
│  ├─ styles           # 设计 token、全局样式、AntD 主题
│  └─ utils            # 格式化、脱敏、权限判断、错误处理
├─ DESIGN.md           # React 版设计规范
├─ PRODUCT.md          # 产品边界与隐私规则
└─ package.json
```

### 应用壳层

React 版保留老后台工作模式：

- 左侧父子菜单：11 个父级菜单，按老项目顺序排列。
- 顶部栏：系统名称、租户/机构上下文、当前用户、退出。
- 可关闭页签：替代 iframe tabs，支持打开多个业务入口。
- 中央工作区：承载列表页、工作台页、报表页、打印页。
- 权限控制：菜单显示、路由访问和按钮行为都基于后端会话/权限信息。

壳层必须避免 iframe。页面状态通过 React Router、URL 查询参数、页签状态和 Query cache 管理。

### API 与会话

React 版复刻现有 Vue API client 的协议行为：

- 登录：`/auth-api/api/admin/auth/login`
- 当前用户：`/auth-api/api/admin/auth/me`
- 刷新 token：`/auth-api/api/admin/auth/refresh`
- 登出：`/auth-api/api/admin/auth/logout`
- 业务接口继续走现有网关前缀。

实现要求：

- access token 统一注入 `Authorization: Bearer ...`。
- 401 后按现有语义尝试刷新，失败则回登录页。
- 下载接口使用 Blob，不把文件流当 JSON。
- 请求错误统一展示业务可读信息，同时保留诊断信息入口。

### 菜单与页面地图

React 路由以老项目 11 个父级菜单和 68 个二级入口为基线。第一阶段至少把所有入口注册到菜单和路由中：

- 已实现页面：进入真实 React 页面。
- 未完成页面：进入“迁移说明页”，显示页面名称、老路由、所属父级、迁移状态和后续实现边界。

这样可以先恢复完整信息架构，避免新前端再次退化成少量抽象工作台。

### 页面类型

按老项目前端审查结果，React 版抽象以下页面模板：

- 标准列表页：标题、筛选、操作栏、表格、分页。
- 配置 CRUD 页：列表 + 新增/编辑抽屉 + 删除/停用确认。
- 权限分配页：树形权限、角色/用户选择、固定提交栏。
- 订单工作台页：订单列表、处方分段、详情抽屉、固定操作栏。
- 生产作业页：调剂、复核、发货、打印等高频操作。
- 报表页：时间/机构/人员筛选、汇总表、导出、明细钻取。
- 导入页：模板下载、文件选择、上传、结果和失败明细。
- 打印页：固定纸张尺寸预览、打印任务结果、历史记录。
- 大屏页：独立深色全屏路由，不套普通后台壳层。

## 视觉设计

视觉仍沿用 `frontend/admin-web/DESIGN.md` 的产品原则，但 React 版需要在 `frontend/admin-react/DESIGN.md` 中重新落地。

关键方向：

- 保留老项目高密度、列表优先、操作紧邻数据的工作习惯。
- 替换旧样式为现代企业后台：白色内容面、浅灰工作区、清晰 1px 边框、克制蓝色主色。
- 不做营销式首页、大卡片堆砌、渐变背景、装饰图形。
- 标准页面首屏必须看到标题、筛选区、表格主体和主要操作。
- 表格列多时使用受控横向滚动，不能压缩到文字重叠。
- 订单详情和打印页面按业务分段，不把所有字段塞进单一横向表格。

## 第一阶段代表页面

第一阶段选择能覆盖主要结构的页面样板：

| 类型 | 建议页面 | 验证重点 |
| --- | --- | --- |
| 系统配置 | 用户管理或角色管理 | CRUD、权限按钮、状态标签、编辑抽屉 |
| 订单列表 | 处方列表 | 多条件筛选、宽表格、分页、详情入口 |
| 订单作业 | 处方复核或订单审核 | 表单/工作台、固定操作栏、提交状态 |
| 物流/煎煮 | 设备列表查询或订单发货查询 | 设备/作业状态、行操作、打印入口 |
| 报表 | 处方数量统计 | 时间筛选、汇总表、导出、分页 |

具体优先级在实施计划中确定。

## 风险

- React 重建是前端技术栈切换，工作量明显大于 Vue 局部改皮。
- 现有 Vue 页面包含一些可用 API 封装和类型，迁移时要避免遗漏接口细节。
- 老项目截图展示的是旧系统结果，不一定覆盖所有弹窗、异常和打印插件状态。
- 68 个菜单一次性全功能完成风险高，必须先做架构和样板，再分阶段补齐。
- 部署入口切换会影响线上访问，需要保留 Vue 版回退路径。

## 回滚路径

- React 工程独立位于 `frontend/admin-react`，不破坏 Vue 工程。
- 部署切换前，现有 Vue 版仍可作为当前可用入口。
- React 版每阶段独立提交；如代表页面失败，可回退 React 提交或不切换部署入口。
- 不改后端接口和数据库，回滚不涉及数据迁移。

## 验证计划

设计和实施阶段必须执行：

- 检查 React 工程 `npm run build`。
- 登录、刷新、登出、token 过期路径可用。
- 11 个父级菜单、68 个入口均可在左侧导航定位。
- 代表页面完成关键路径：查询、重置、分页、打开详情/编辑、保存/关闭、导出或打印入口。
- 桌面 1366/1440 宽度下无文本重叠、按钮挤压、表格失控溢出。
- 窄屏下菜单、筛选区和表格滚动行为可用。
- Impeccable 对 React 工程和代表页面做审查与打磨。

## 验收标准

- `frontend/admin-react` 能独立安装、启动和构建。
- React 主壳层恢复老项目“左侧父子菜单 + 顶部栏 + 可关闭页签 + 中央工作区”的操作习惯。
- 菜单地图覆盖老项目 11 个父级菜单和 68 个二级入口。
- 代表页面结构与老截图一致，视觉为现代后台风格。
- 不依赖 JSP、iframe、jQuery、EasyUI 或 Bootstrap。
- 不改变后端接口、权限语义、业务状态流转和数据库。
- Vue 工程仍保留，直到用户确认切换部署入口。

## 用户确认结果

- 用户确认不再继续修 Vue 前端，改为 React 重建。
- 用户确认采用方案 A：新建 `frontend/admin-react` 并行开发，验证通过后再替换部署入口。
