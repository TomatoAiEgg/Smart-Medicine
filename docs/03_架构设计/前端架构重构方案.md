# 前端架构重构方案

## 1. 重构目标

前端目标不是重新设计一个和老系统无关的新后台，而是把 `zhyfsupport` 的内部运营后台迁移为 Vue 3 管理端。

核心目标：

- 还原老后台的业务菜单和操作路径。
- 用现代前端结构替代 JSP + iframe + EasyUI。
- 页面围绕真实业务动作设计，不做展示型空壳。
- 前端只调用后端 API，不直接承载业务规则。
- 支持后续权限菜单、状态标签、导入导出、打印、监控跳转。

## 2. 当前问题

当前 `frontend/admin-web` 主要问题：

- 已使用 `vue-router` 建立静态菜单和路由注册表，老后台菜单均有 URL 入口。
- 多个路由仍复用聚合工作区，页面字段和交互尚未逐页按老系统验收。
- 部分页面只有查询或前端预览，后端权限、导入、打印、群发和真实外部服务仍未闭环。
- 路由存在不等于业务完成，必须按筛选、列表、详情、动作、错误状态和审计逐页验收。

## 5. 页面设计原则

- 运营后台以表格和筛选为核心。
- 查询条件必须贴近老系统字段，不用过度抽象。
- 详情页必须显示订单、处方、药品明细、状态日志、操作记录。
- 状态显示用中文业务状态，不直接展示内部枚举或 UUID。
- 行内操作必须靠近数据行。
- 高风险操作使用确认弹窗并展示影响范围。
- 导入导出和打印入口单独封装，避免每个页面重复实现。

## 6. 当前范围和下一步

当前已完成 Vue Router、静态菜单、订单主链路页面、机构/参数/药品/物流/煎煮/短信/标签/报表/运维页面入口以及 TDesign 基础组件接入。

下一步按老系统页面逐项验收：

- 校准筛选字段、表格列、详情分段和中文状态。
- 接通真实后端接口，移除仅前端模拟或只读替代动作。
- 补齐登录、菜单和按钮权限后的无权限状态。
- 补齐批量导入、真实打印、短信群发、导出任务和失败结果。
- 使用真实业务样例验收审核、调剂、复核、煎煮、物流和补偿闭环。

## 7. 前端和后端契约

所有页面调用 `/api/admin/**` 后台管理 API。

统一返回结构：

```json
{
  "code": "SUCCESS",
  "message": "ok",
  "data": {}
}
```

分页结构：

```json
{
  "items": [],
  "page": 1,
  "pageSize": 20,
  "total": 100
}
```

前端展示状态必须使用后端返回的 `statusLabel`，不要在页面硬编码所有状态。链路追踪由 SkyWalking 负责，前端不依赖链路追踪编号字段；联调排查时记录接口路径、请求时间、订单号、操作人和错误码。

## 8. 验收标准

- `npm run build` 通过。
- 订单主链路页面可以通过 URL 直接访问。
- 页面刷新后路由状态不丢失。
- 订单列表、详情、审方、调剂、复核能调用真实接口。
- 表格、按钮、弹窗在常见桌面宽度下不重叠。
- 错误信息能显示后端返回的业务提示；排障信息通过 SkyWalking、服务日志和订单号关联。
