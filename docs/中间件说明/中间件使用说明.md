# 中间件使用说明

## 1. 中间件清单

当前开发测试中间件部署在云服务器：

```text
47.120.55.53
```

主要组件：

- PostgreSQL
- Redis
- RocketMQ
- Nginx
- SkyWalking
- Prometheus
- Grafana
- Loki 或日志采集组件
- 1Panel

## 2. PostgreSQL

用途：

- 订单主数据。
- 处方主数据。
- 流程任务。
- 煎煮任务。
- 物流单。
- 回调记录。
- 报表查询。
- 运维审计。

调用方式：

- 后端服务使用 MyBatis-Plus 作为主持久化框架。
- 复杂报表和遗留字段映射使用 MyBatis Mapper XML。
- 表结构通过 Flyway 管理。
- 前端不直接访问数据库。

使用规则：

- 每个状态变化都要写状态日志。
- 查询接口必须分页。
- 报表查询必须限制时间范围。
- 重要业务表必须按查询条件建索引。
- 不允许 Service 层拼接 SQL。
- 不允许跨服务随意直接修改其他服务的数据。

## 3. Redis

用途：

- 字典缓存。
- 系统参数缓存。
- 机构配置缓存。
- 白名单缓存。
- 短期幂等标记。
- 分布式锁候选。
- 会话或验证码候选。

使用规则：

- Redis 不能作为唯一可靠数据源。
- 缓存必须有过期时间或刷新机制。
- 缓存 key 必须带业务前缀。
- 分布式锁必须设置过期时间。
- 敏感值不直接明文写入 Redis。

推荐 key：

```text
zhyf:dict:{type}
zhyf:system-config:{key}
zhyf:institution-app:{appKey}
zhyf:ip-whitelist:{institutionId}
zhyf:idempotent:{businessType}:{businessId}
zhyf:lock:{resource}:{id}
```

## 4. RocketMQ

用途：

- 订单创建事件。
- 审方结果事件。
- 调剂完成事件。
- 复核完成事件。
- 煎煮事件。
- 物流事件。
- 回调补偿事件。

推荐 topic：

```text
zhyf-order-event
zhyf-prescription-event
zhyf-decoction-event
zhyf-logistics-event
zhyf-callback-event
```

使用规则：

- 业务服务先写 `event_outbox`，再由 `message-service` 发布。
- 消费端必须写 `message_consume_log` 做幂等。
- 消费失败必须记录原因。
- 可重试失败进入重试。
- 不可重试失败进入人工处理或死信。

事件 payload 至少包含：

- `eventId`
- `tenantId`
- `orderId`
- `orderNo`
- `eventType`
- `occurredAt`
- `source`

## 5. Nginx

用途：

- 承载前端静态文件。
- 反向代理 gateway。
- 统一公网入口。
- 后续配置 HTTPS。

推荐路由：

```text
/      -> admin-web 静态文件
/api/  -> gateway
```

使用规则：

- 公网入口优先只开放 Nginx。
- 后端服务端口不直接公网暴露。
- 上传大小、超时、跨域按业务配置。

## 6. SkyWalking

用途：

- 服务拓扑。
- 分布式调用链。
- 慢接口分析。
- 跨服务错误定位。

接入要求：

- 所有 Java 服务启动时挂 SkyWalking agent。
- service name 使用服务名。
- 前后端接口不把链路追踪 ID 当业务字段。
- 联调排查按请求时间、endpoint、订单号、服务拓扑定位。

## 7. Prometheus 和 Grafana

Prometheus 用途：

- 抓取服务指标。
- 抓取 JVM 指标。
- 抓取容器和主机指标。

Grafana 用途：

- 服务健康看板。
- JVM 看板。
- 容器资源看板。
- 业务链路看板。

使用规则：

- 开发测试环境可降低采集频率。
- 不把 Prometheus 长期当业务审计数据库。
- 关键业务统计仍然落数据库。

## 8. 日志采集

用途：

- 聚合容器日志。
- 按服务、订单号、处方号、事件 ID 查询日志。
- 排查联调和线上异常。

使用规则：

- 日志要结构化。
- 日志要包含业务关联键。
- 不记录明文密钥。
- 保留周期按磁盘容量控制。

## 9. 中间件调用链

订单创建主链路：

```text
gateway
 -> order-service
 -> PostgreSQL(order_main, prescription, event_outbox)
 -> message-service
 -> RocketMQ
 -> workflow-service
 -> PostgreSQL(workflow_task, order_status_log)
```

回调补偿链路：

```text
logistics-service/workflow-service
 -> callback-service
 -> PostgreSQL(callback_record)
 -> HTTP callback
 -> failed retry/dead
 -> ops-service 查询和人工处理
```

缓存链路：

```text
admin 修改字典/机构/白名单
 -> PostgreSQL
 -> Redis 缓存刷新
 -> gateway/auth-institution 读取缓存
```
