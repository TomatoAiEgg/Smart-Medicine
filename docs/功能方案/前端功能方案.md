# 前端功能方案

## 1. 功能目标

`admin-web` 前端以老后台 `zhyfsupport` 为业务基线，目标不是做一个聚合调试台，而是恢复老后台 11 个一级菜单、68 个二级菜单对应的真实业务操作能力。

当前新前端已经建立覆盖老后台菜单的静态路由和页面入口，并接入部分真实查询与操作接口；仍需按本方案逐页验收字段、业务动作、权限、导入、打印和异常状态，不能按路由数量判定完成。

前端重构原则：

- 二级菜单必须成为真实路由或明确的页面入口。
- 聚合页只作为概览或过渡页面，不能吞掉老系统菜单粒度。
- 查询、列表、详情可以先做骨架；会推进业务状态的动作必须等后端状态机、幂等、权限和审计接口完成后再验收。
- 所有页面都必须围绕真实业务动作设计，不做空壳展示。
- 页面展示业务字段和中文状态，不把 UUID、原始日志、系统内部枚举作为主信息。

## 2. 前端架构目标

当前 `admin-web` 已使用 `vue-router` 支持 URL 直达和刷新恢复，`activeView` 只作为路由元数据映射后的页面组件选择状态。

目标结构：

```text
frontend/admin-web/src
├── app
│   ├── router.ts       # 真实路由，支持刷新直达
│   ├── menu.ts         # 68 个菜单静态树，后续接后端权限菜单
│   └── AppLayout.vue
├── api
│   ├── admin.ts
│   ├── institution.ts
│   ├── order.ts
│   ├── prescription.ts
│   ├── workflow.ts
│   ├── drug.ts
│   ├── decoction.ts
│   ├── logistics.ts
│   ├── message.ts
│   ├── report.ts
│   └── ops.ts
├── components
│   ├── AdminTable.vue
│   ├── SearchForm.vue
│   ├── StatusTag.vue
│   ├── PageHeader.vue
│   ├── FormDialog.vue
│   ├── ImportDialog.vue
│   └── PrintAction.vue
└── features
    └── <domain>/<Page>.vue
```

路由规则：

- 每个老后台二级菜单对应一个新路由。
- 旧路由只作为迁移依据，不直接暴露给新前端。
- 详情、编辑、导入、打印、导出、补偿可以是子路由、抽屉或弹窗。
- 第一阶段可静态菜单；权限服务完成后改为后端返回菜单树和按钮权限。

### 5.1 RBAC 角色与权限菜单实施状态

- `/system/roles` 已从历史角色标识聚合页切换为规范化 RBAC 角色页，支持非内置角色新增、编辑、删除、启停、权限分组勾选和机构范围选择。
- 内置角色只读；有关联用户的角色不可删除；无 `system:write` 或非租户全域管理员只能查看。
- `/system/users` 角色字段改为启用角色选择，展示角色名称和标识，保存时由后端同步规范化用户角色关系。
- 左侧菜单按当前会话权限裁剪，直接访问无权路由会返回工作台；工作台无 `ops:read` 时不请求运维概览，只显示权限提示。
- 权限或数据范围变更会由 V48 自动吊销关联会话；用户下一次请求进入登录页，重新登录后获得新菜单和权限。gateway 的 401/403 校验继续作为最终安全边界。

### 5.2 登录会话刷新与强制下线

- 浏览器 `sessionStorage` 保存访问令牌、一次性刷新令牌和会话展示信息；关闭标签页后不保留长期登录，不使用 `localStorage`。
- API 收到 401 时只启动一个刷新请求；刷新成功后轮换两类令牌并重放原请求，并发请求共享同一刷新过程，避免旧刷新令牌被并发重放。
- 刷新失败、会话被吊销或刷新令牌到期时清空本地会话并回到登录页；网络或后端错误不会在页面中展示令牌内容。
- 正常退出调用后端吊销接口后再清空浏览器会话，不再只是前端删除缓存。
- 工号管理的“强制下线”仅对租户全域系统管理员显示为可用动作，当前账号不可强制下线自身，操作前二次确认并展示实际吊销会话数。
