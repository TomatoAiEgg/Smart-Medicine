# 后端功能方案

## 1. 功能目标

后端功能按“内部后台 + 外部协议 + 运维补偿”三类能力建设。

## 2. 内部后台能力

### 订单能力

- 订单分页查询。
- 订单详情查询。
- 订单进度查询。
- 订单状态日志。
- 订单锁定、解锁。
- 订单备注。
- 修改地址。
- 修改处方。
- 处方重打。
- 订单签收。

### 流程能力

- 创建审方任务。
- 审方通过。
- 审方驳回。
- 创建调剂任务。
- 完成调剂。
- 创建复核任务。
- 完成复核。
- 记录操作人、备注、时间和结果。

### 煎煮能力

- 处方可操作列表。
- 处方绑定设备。
- 煎煮开始。
- 煎煮完成。
- 煎煮取消。
- 煎煮终止。
- 加水完成通知。
- 设备作业记录。

### 物流能力

- 待打包订单。
- 创建物流单。
- 发货。
- 签收。
- 轨迹记录。
- 物流配置维护。
- 物流回调记录。

### 报表能力

- 订单状态统计。
- 处方数量统计。
- 绩效统计。
- 药材统计。
- 对账查询。
- CSV 或 Excel 导出。

### 运维能力

- Outbox 查询。
- 消费日志查询。
- 订单校验记录。
- API 访问日志。
- 回调失败记录。
- 集成重试任务。
- 健康概览。
- 人工重试或标记处理。

## 3. 外部协议能力

### 机构订单接口

- 创建订单。
- 取消订单。
- 查询订单。
- 更新地址。
- 查询平台订单号。

### PDA 接口

- PDA 登录。
- 获取煎煮设备。
- 绑定处方。
- 操作煎煮状态。
- 获取可操作处方。
- 标签打印初始化。
- 标签打印记录。
- 物流出库。

### MES 接口

- 根据桶号取加水量。
- 加水完成通知。
- 获取处方煎煮信息。
- 煎煮结果回调。
- 复核完成推送处方。

### 物流接口

- 创建物流单。
- 取消物流单。
- 查询面单打印信息。
- 打印面单。
- 查询费用。
- 接收物流回调。

## 4. 第一阶段功能

第一阶段以后端订单主链路为准：

- 机构下单。
- 订单落库。
- Outbox 事件。
- 审方任务。
- 调剂任务。
- 复核任务。
- 订单进度。
- 状态日志。
- 后台订单管理 API。

## 5. 功能验收

- 外部创建订单后后台可查询。
- 审方通过后生成调剂任务。
- 调剂完成后生成复核任务。
- 复核完成后订单进入待煎煮或已复核状态。
- 每次状态变化都有日志。
- 每个后台动作都有操作人和来源。
- 失败动作不产生脏状态。

## 6. 全量后端重构范围

后端重构范围以老 `zhyfsupport` 内部后台和 `zhyf-api` 外部接口/异步消费为共同基线。当前文档不再只描述第一阶段订单主链路，而是作为后端全量实施清单维护。

全量范围分为 12 个能力域：

| 能力域 | 老系统来源 | 新系统承载 | 必须恢复的能力 |
| --- | --- | --- | --- |
| 系统权限 | `tb_user`、`tb_role`、`tb_menu`、用户/角色/菜单控制器 | `admin-service` / `auth-institution` | 用户、角色、菜单、授权、操作审计 |
| 参数配置 | 字典、参数、煎煮中心、工号管理 | `admin-service` | 字典、系统参数、煎煮中心、操作员工号 |
| 机构接入 | 机构、接口、权限、白名单、签名校验 | `auth-institution`、`gateway` | 机构档案、应用、API 权限、IP 白名单、回调配置 |
| 订单处方 | 订单、处方、明细、地址、处方修改、重打 | `order-service`、`prescription-service` | 下单、取消、查询、修改地址、修改处方、重打、签收 |
| 流程作业 | 审核、调剂、复核、订单走流程 | `workflow-service` | 审核、调剂、复核、人工推进、任务锁定、绩效事件 |
| 药品主数据 | 药品目录、索引、区域、导入、日志 | `drug-service` | 药品、索引、区域、批量导入、药品匹配日志 |
| 煎煮设备 | 设备、处方设备绑定、打码机、加水桶、云打印 | `decoction-service`、`device-service` | PDA、MES、设备、绑定、加水桶、作业记录、打印记录 |
| 物流履约 | 物流规则、费用、发货、轨迹、打单、合单、未签收 | `logistics-service` | 费用规则、发货、打单、轨迹、合单、签收、未签收跟进 |
| 消息回调 | ActiveMQ 消费、MQ 消息查询、状态回调 | `message-service`、`callback-service` | Outbox、RocketMQ、消费日志、回调、重试、死信 |
| 短信标签 | 短信模板、短信记录、标签设置、标签打印 | `sms-service`、`print-service` | 模板、发送、记录、打印任务、重打 |
| 报表对账 | 处方统计、绩效、药材、对账、导出 | `report-service` | 16 个老报表入口、异步导出、统计口径 |
| 运维问题 | 异常日志、订单流程、MQ 消息、问题件登记 | `ops-service` | 异常、流程、MQ、回调失败、问题件、人工补偿 |

## 7. 后端服务实施清单

### 7.1 `gateway`

职责：

- 统一外部入口。
- 兼容老机构订单接口路径。
- 接入签名校验、时间戳校验、IP 白名单、接口权限、限流和访问日志。
- 对管理端 API 做统一转发和认证入口。

必须实现：

- 机构接口限流：按 `tenantId + institutionId + methodName` 维度限流。
- 访问日志：记录请求路径、机构、来源地址、结果码、耗时。
- 失败响应兼容：鉴权失败、白名单失败、签名超时、签名错误要保持清晰业务码。
- 灰度开关：外部旧协议可按机构切换到新服务 adapter。

### 7.2 `auth-institution`

职责：

- 维护租户、机构、机构应用、应用凭证、接口权限、IP 白名单、回调配置。
- 为 gateway 和其他服务提供内部查询接口。
- 后续承接后台用户、角色、菜单权限基础。

必须实现：

- 机构 CRUD。
- 应用凭证启停。
- 接口定义 CRUD。
- 机构接口授权。
- IP 白名单维护。
- 后台用户、角色、菜单查询和授权。
- 接入配置变更操作日志。

### 7.3 `order-service`

职责：

- 负责订单主聚合、订单状态机、订单查询、订单修改和订单操作。
- 承接外部下单、取消、查询、修改地址、平台订单号查询。

必须实现：

- 创建订单：订单、处方、明细、状态日志、Outbox 同事务提交。
- 幂等：`tenantId + institutionId + externalOrderNo` 唯一。
- 取消订单：校验当前状态，写状态日志，发状态事件。
- 查询订单：支持平台订单号、外部订单号、机构、状态、时间范围。
- 修改地址：写地址变更记录，不直接覆盖无审计字段。
- 修改处方：写处方变更记录，必要时触发重新校验。
- 订单锁定/解锁：防止多人同时操作高风险订单。
- 订单走流程：仅限授权角色，必须写原因和操作审计。
- 订单签收：支持物流回调和后台人工签收两种来源。

### 7.4 `prescription-service`

职责：

- 负责处方、处方明细、处方状态、处方修改、处方重打。
- 当前早期可由 `order-service` 承载表结构，但业务边界必须独立。

必须实现：

- 处方列表和详情。
- 处方明细查询。
- 处方修改申请和审核。
- 处方重打记录。
- 药品匹配结果查询。
- 处方状态日志。
- 处方与订单状态联动规则。

### 7.5 `workflow-service`

职责：

- 负责审核、调剂、复核和人工任务。
- 管理任务状态机、任务锁、人员绩效事件。

必须实现：

- 审核任务生成、领取、通过、驳回。
- 调剂任务生成、领取、完成、打印记录。
- 复核任务生成、领取、完成、异常处理。
- 并发控制：同一任务只能被一个操作提交成功。
- 任务状态机：不允许非法跳转。
- 绩效事件：记录审核员、调剂员、复核员工作量。
- 失败补偿：任务状态和订单状态不一致时能在运维后台定位。

### 7.6 `drug-service`

职责：

- 负责药品主数据、药品索引、药材区域、导入和匹配。

必须实现：

- 药品目录 CRUD。
- 药品索引 CRUD。
- 药材区域维护。
- 药品目录导入。
- 药品索引导入。
- 导入预检、错误明细、结果记录。
- 药品索引操作日志。
- 处方药品匹配任务和匹配失败记录。

### 7.7 `decoction-service` 和 `device-service`

职责：

- 负责 PDA、MES、设备、处方绑定、加水桶、打码机、云打印。

必须实现：

- PDA 登录和权限校验。
- 可操作处方列表。
- 处方绑定设备。
- 煎煮开始、完成、取消、终止。
- MES 按水桶查询加水量。
- MES 加水完成通知。
- MES 获取处方煎煮信息。
- 煎煮状态回调。
- 设备档案和启停。
- 打码机/PDA 关系配置。
- 加水桶管理。
- 云打印记录查询和重打。

### 7.8 `logistics-service`

职责：

- 负责物流规则、发货、面单、轨迹、合单、签收和未签收跟进。

必须实现：

- 物流费用规则维护。
- 机构地址费用维护。
- 待发货订单查询。
- 创建物流单。
- 取消物流单。
- 查询面单信息。
- 打印和重打面单。
- 物流轨迹回调兼容。
- 合单发货。
- 未签收订单筛选和跟进记录。
- 发货、运输中、签收状态事件。

### 7.9 `message-service`

职责：

- 负责 Outbox 发布、RocketMQ 生产、消费幂等、消费日志和消息补偿。

必须实现：

- Outbox 扫描、发布、重试、超时释放。
- RocketMQ Topic 和 ConsumerGroup 管理。
- 消费日志唯一约束：`consumerGroup + eventId`。
- 消费失败原因记录。
- 重试和死信状态。
- 人工重放消息。
- 旧 ActiveMQ 队列语义迁移到 RocketMQ 事件。

### 7.10 `callback-service`

职责：

- 负责机构状态回调、物流回调补偿和失败重试。

必须实现：

- 回调记录创建。
- HTTP 回调发送。
- 失败退避重试。
- 最大重试后进入 `DEAD`。
- 人工重放。
- 人工标记成功/失败。
- 回调响应报文和失败原因留存。

### 7.11 `sms-service` 和 `print-service`

职责：

- 负责短信模板、短信发送、标签模板、标签打印和重打。

必须实现：

- 短信模板 CRUD。
- 单发短信。
- 短信发送记录。
- 短信失败重试。
- 标签模板 CRUD。
- 标签打印任务。
- 打印失败记录。
- 标签重打记录。

### 7.12 `report-service`

职责：

- 负责统计、对账、绩效和导出。

必须实现：

- 处方数量统计。
- 机构处方数量统计。
- 审核员绩效统计和明细。
- 调剂员绩效统计和明细。
- 复核员绩效统计和明细。
- 煎煮员绩效统计和明细。
- 物流员绩效统计和明细。
- 机构药材统计。
- 处方对账列表。
- 药材明细列表。
- 药材用量统计。
- 大数据量导出任务。

### 7.13 `ops-service`

职责：

- 负责运维排错、异常查询、问题件登记、消息和回调补偿入口。

必须实现：

- 订单流程查询。
- 处方流程查询。
- 异常日志查询。
- MQ 消息查询。
- Outbox 查询。
- 消费日志查询。
- 回调失败查询。
- 集成失败查询。
- 问题件登记、处理、关闭。
- 健康概览。
- 人工重试、重放、标记处理。

### 7.14 `integration-service` 和 `portal-service`

职责：

- 负责智慧云、定制机构、社康、医院查单、地址补录等外围协议。

必须实现：

- 智慧云处方同步、修改、取消和状态回调。
- 定制机构下单/取消协议 adapter。
- 医院查单。
- 地址补录申请。
- 地址补录回推。
- 社康消息归档。
- 社康状态回写。
- 外围重试任务和失败聚合。

## 8. 分布式治理落地清单

### 8.1 高并发入口

必须重点治理：

- 外部机构批量推单。
- 查询订单和医院查单。
- PDA/MES 高频状态回调。
- 物流轨迹批量回调。
- 报表大范围查询和导出。

落地要求：

- gateway 按机构、接口、IP、应用维度限流。
- Redis 只做短期限流、锁和缓存，不保存唯一业务事实。
- 数据库用唯一索引保证最终防重。
- 报表查询和导出不影响订单主链路。

### 8.2 事务一致性

必须使用本地事务的场景：

- 创建订单时写订单、处方、明细、状态日志和 Outbox。
- 审核、调剂、复核任务完成时写任务、操作记录和事件。
- 发货、签收时写物流单、轨迹、状态日志和事件。
- 问题件登记和处理记录。

跨服务一致性统一使用：

```text
本地事务
 -> event_outbox
 -> RocketMQ
 -> 消费幂等
 -> 重试/死信/人工补偿
```

### 8.3 幂等与并发控制

必须有幂等键：

- 外部下单：`tenantId + institutionId + externalOrderNo`。
- 外部取消：`tenantId + institutionId + externalOrderNo + action`。
- PDA/MES 操作：`operationId` 或业务动作组合键。
- 物流回调：`logisticsNo + traceStatus + traceTime`。
- MQ 消费：`consumerGroup + eventId`。
- 后台任务动作：`taskId + action + version`。

必须使用乐观锁或条件更新：

- 审核任务。
- 调剂任务。
- 复核任务。
- 订单状态推进。
- 煎煮任务状态。
- 物流单状态。

### 8.4 补偿和死信

所有异步任务必须能回答：

- 任务是否产生。
- 任务是否发送。
- 消费方是否收到。
- 消费是否成功。
- 失败原因是什么。
- 下一次重试时间是什么。
- 是否进入死信。
- 谁人工处理过。

运维后台必须能操作：

- 重试 Outbox。
- 重放 MQ 消费。
- 重放机构回调。
- 重放集成任务。
- 标记死信已处理。
- 登记问题件。

### 8.5 可观测性

后端日志和指标必须覆盖：

- gateway 访问日志。
- 每次订单状态变化。
- 每次任务操作。
- 每次 Outbox 发布。
- 每次 MQ 消费。
- 每次外部 HTTP 回调。
- 每次失败重试。
- 每次人工补偿。

排障维度至少支持：

- 平台订单号。
- 外部订单号。
- 处方号。
- 机构编号。
- 事件 ID。
- 回调 ID。
- 操作人。
- 请求时间。

## 9. 后端实施顺序

后端按以下顺序推进，避免先做边缘页面导致核心链路返工：

1. 补齐业务基线：确认老菜单、旧接口、旧表字段和新领域模型映射。
2. 补齐系统权限和机构接入：菜单、角色、机构、接口权限、白名单、签名和限流。
3. 强化订单处方主链路：创建、取消、查询、修改地址、修改处方、重打、签收。
4. 完整落地流程作业：审核、调剂、复核、人工推进、任务锁和绩效事件。
5. 补齐药品主数据：目录、索引、导入、匹配和日志。
6. 补齐煎煮设备：PDA、MES、设备、绑定、加水桶、打印记录。
7. 补齐物流履约：规则、费用、打单、合单、轨迹、未签收跟进。
8. 补齐消息回调：消费日志、死信、回调重试、人工补偿。
9. 补齐短信标签：模板、发送、打印和重打。
10. 补齐报表对账：统计、明细、导出和性能优化。
11. 补齐运维问题：异常、MQ、流程、问题件和健康概览。
12. 做压测、容量评估、监控告警和部署验收。

## 10. 后端完成标准

后端不能只按接口数量验收。完整重构完成时至少满足：

- 老后台每个菜单都有后端 API 或明确的替代接口。
- `zhyf-api` 主要外部协议都有兼容入口或 adapter。
- 创建订单主链路具备本地事务、Outbox、MQ、幂等和补偿。

- 报表统计不阻塞订单主链路。
