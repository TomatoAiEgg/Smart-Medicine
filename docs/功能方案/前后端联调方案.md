# 前后端联调方案

## 1. 联调原则

- 先定接口契约，再分别开发前端和后端。
- 前端不发明字段。
- 后端不随意改变返回结构。
- 接口返回业务结果，不把链路追踪 ID 当业务字段返回。
- 分布式调用链统一交给 SkyWalking、网关日志和服务日志处理。
- 联调以订单主链路为第一目标。

## 2. 统一返回结构

成功返回：

```json
{
  "code": "SUCCESS",
  "message": "ok",
  "data": {}
}
```

错误返回：

```json
{
  "code": "ORDER_STATUS_INVALID",
  "message": "当前订单状态不允许复核",
  "data": null
}
```

分页返回：

```json
{
  "items": [],
  "page": 1,
  "pageSize": 20,
  "total": 100
}
```

说明：

- 前端不依赖链路追踪编号字段。
- gateway 和后端服务负责接入 SkyWalking agent。
- 服务间调用通过 SkyWalking 上下文自动串联。
- 如需人工排障，按请求时间、接口路径、订单号、操作人和 SkyWalking 服务拓扑定位。

## 4. 联调顺序

### 第一步：订单列表

后端提供订单分页接口，前端完成列表和筛选。

验收：

- 能查询订单。
- 能按状态、机构、订单号筛选。
- 分页正常。
- 空数据状态正常。

### 第二步：订单详情

后端提供订单详情和进度接口，前端完成详情页。

验收：

- 能查看订单信息。
- 能查看处方明细。
- 能查看状态日志。
- 能查看履约进度。

### 第三步：人工动作

后端提供审方、调剂、复核、锁定、解锁、备注、改地址接口。

验收：

- 前端按钮可触发动作。
- 动作成功后刷新状态。
- 动作失败时展示后端业务原因。
- 状态不允许时不能产生错误流转。

### 第四步：链路验证

从外部下单开始完整验证：

```text
创建订单 -> 后台查询 -> 审方 -> 调剂 -> 复核 -> 煎煮 -> 物流 -> 回调
```

验收：

- 前端页面状态和数据库状态一致。
- SkyWalking 能看到 gateway、order-service、message-service、workflow-service、decoction-service、logistics-service、callback-service 的完整调用链。
- Prometheus 能看到服务指标。
- 日志能按订单号、接口路径、操作人和请求时间定位。

### 第五步：事务和幂等验证

围绕同一订单重复或并发触发关键动作：

- 重复创建同一个外部订单号。
- 两个窗口同时审方同一个任务。
- 重复点击调剂完成。
- 重复提交 PDA/MES `operationId`。
- 模拟 MQ 消费重复投递。

验收：

- 不产生重复订单。
- 不产生重复任务。
- 不重复推进订单状态。
- 并发冲突返回明确业务提示。
- 失败事件可以在运维页面看到并重试。

## 5. 本地和云服务器联调方式

前端本地启动：

```text
cd frontend/admin-web
npm run dev
```

后端优先连接云服务器 `47.120.55.53` 上的开发中间件。

常用后端启动脚本：

```text
scripts/run-gateway-local.ps1
scripts/run-order-service-local.ps1
scripts/run-message-service-local.ps1
scripts/run-auth-institution-local.ps1
```

前端通过 Vite proxy 或 gateway 调用后端，不直接访问各个业务服务端口。

## 6. SkyWalking 联调排查方式

前端发现接口异常时记录：

- 页面。
- 操作按钮。
- 接口路径。
- 请求时间。
- 订单号或处方号。
- 操作人。
- 错误码和错误消息。

后端排查顺序：

1. 在 SkyWalking 按服务名和时间窗口查看慢调用或异常调用。
2. 按接口路径定位 endpoint。
3. 按订单号或处方号查询业务日志和操作日志。
4. 按服务拓扑确认异常发生在 gateway、业务服务、数据库、MQ 还是外部回调。
5. 回到数据库核对状态日志和操作记录。

## 7. 联调记录要求

每次联调至少记录：

- 接口路径。
- 请求参数摘要。
- 返回结果。
- 请求时间。
- SkyWalking 查询条件或截图。
- 前端页面表现。
- 后端日志结论。
- 数据库状态。
- 是否通过。
