# 文档治理规则

本文件约束 `docs` 下的正式项目文档。`cyiae-brochure-h5` 和 `superpowers` 是独立交付物或历史计划目录，不纳入本项目正式文档审查和分类。

## 目录职责

| 目录 | 只应包含 |
| --- | --- |
| `00_项目总览` | 项目说明、模块清单、项目上下文、现状审查报告、文档入口 |
| `03_架构设计` | 总体架构、服务边界、数据边界、事件边界、事务和专项架构设计 |
| `04_开发规范` | 本项目编码、分层、变更、协作和安全规范 |
| `05_测试压测` | 功能测试、真实用户模拟、接口验收、压力/容量/流量/故障测试 |
| `06_部署运维` | 本地环境、服务器环境、部署、发布、回滚、备份和日常运维 |
| `99_项目记录` | 已发生的新增、修改、删除、联调、发布和验收记录 |
| `中间件说明` | PostgreSQL、Redis、RocketMQ、Nginx 等中间件的用途和可靠性说明 |
| `功能方案` | 新增或重构功能的业务范围、流程、接口和验收方案 |
| `数据设计` | 表字段、索引、迁移、数据治理、分区和分库分表方案 |
| `监控说明` | 指标、日志、链路、告警、看板和监控闭环说明 |

## 维护规则

1. 新文档先按职责归类，不在 `docs` 根目录堆放普通说明文件。
2. 老系统审查和新系统现状审查放在 `00_项目总览`，二者不得混写。
3. 架构目标、当前实现和历史记录必须明确区分，不能把规划写成已经交付。
4. 功能变化先更新 `功能方案`；表结构变化同步更新 `数据设计` 和 Flyway；部署变化更新 `06_部署运维`。
5. 每次新增、修改、移动或删除正式文档，都在 `99_项目记录/项目记录.md` 追加事实记录。
6. 历史项目记录原则上只追加，不改写当时事实；路径迁移通过新记录说明。
7. 文档使用仓库相对路径，避免本机绝对链接；外部来源路径只作为审查依据时可保留文字记录。
8. 文档、示例和日志不得保存密码、令牌、私钥、验证码、真实患者信息或云账号敏感原文。
9. 压测与容量验证归 `05_测试压测`；监控目录只保留观测口径及测试结果如何映射到监控指标。
10. 部署说明统一归 `06_部署运维`，不再建立并行的 `部署说明` 目录。

## 审查要求

文档交付前至少检查：目录归属、标题与内容一致、内部路径存在、技术栈与代码现状一致、规划/现状口径明确、无敏感信息、`git diff --check` 通过。
