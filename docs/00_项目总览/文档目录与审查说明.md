# 文档目录与审查说明

## 1. 文档定位

`docs` 按项目职责分类，详细维护规则见 `../AGENTS.md`。正式文档不再放在 `docs` 根目录；`cyiae-brochure-h5` 和 `superpowers` 按用户要求不纳入本次审查。

| 目录 | 内容定位 |
| --- | --- |
| `00_项目总览` | 项目入口、模块、上下文、老项目审查、新项目现状审查 |
| `03_架构设计` | 总体架构、前后端架构、事务、事件和设备模拟设计 |
| `04_开发规范` | 本项目分层、编码和协作规范 |
| `05_测试压测` | 接口测试、端到端验收、压测、容量和故障演练 |
| `06_部署运维` | 本地/云端环境、部署、回滚、连接和观测组件运维 |
| `99_项目记录` | 已发生的项目变更和联调事实 |
| `功能方案` | 前端、后端和联调功能范围及验收方案 |
| `数据设计` | 旧表映射、新表、索引、迁移和数据治理 |
| `中间件说明` | 中间件用途、消息可靠性和容灾 |
| `监控说明` | 日志、指标、链路、告警和监控闭环 |

## 4. 保留口径

- `老项目审查报告.md` 中的新项目差距已标记为“审查初期历史基线”，不作为当前完成度。
- `功能方案` 和 `架构设计` 可以描述目标能力，但必须显式区分目标、当前和待验收。
- `99_项目记录` 中的旧路径和旧阶段描述属于历史事实，不批量改写；本次路径变化通过新增记录承接。
- 服务器公网地址可以用于部署和验收说明，但账号、密码、令牌、私钥和验证码不得进入仓库。

## 5. 后续维护入口

1. 项目现状先看 `README.md`、`项目上下文.md` 和 `modules.md`。
2. 旧系统业务基线看 `老项目审查报告.md`。
3. 当前后端风险和改造顺序看 `新项目后端代码审查报告.md`。
4. 功能变化更新 `../功能方案`，架构决策更新 `../03_架构设计`，表结构变化更新 `../数据设计`。
5. 每次文档新增、移动或删除，都追加到 `../99_项目记录/项目记录.md`。
